# 2026-05-07 - Sesion 01

## Contexto de inicio

El usuario reporto que el login de `/admin/login` en el deploy Preview de Vercel quedaba mucho tiempo en `Verificando...` y no entraba al panel desde navegador/celular.

## Diagnostico

- Se reviso `docs/dev-sessions/CURRENT.md` antes de tocar codigo.
- Se consulto la documentacion local de Next.js 16 para Route Handlers y cookies.
- Se probo el endpoint desplegado `/api/admin/auth` con una contrasena falsa y respondio `401`, por lo que la API no estaba caida.
- Se probo el endpoint desplegado usando la `ADMIN_PASSWORD` local sin imprimirla; tambien respondio `401`.
- Conclusion: el deploy Preview no tiene la misma `ADMIN_PASSWORD` que `.env.local`, o no la tiene configurada en Vercel para ese environment.

## Cambios aplicados

- `src/app/api/admin/auth/route.ts`: ahora responde `503` con mensaje claro si `ADMIN_PASSWORD` no esta configurada en el servidor.
- `src/app/admin/login/page.tsx`: el cliente ya no asume que el POST exitoso basta; valida `/api/admin/auth/check` antes de navegar a `/admin`.
- `src/app/admin/login/page.tsx`: se usa `window.location.assign("/admin")` tras confirmar sesion para hacer una entrada limpia al panel protegido.
- `.agent/skills/bug-registry/SKILL.md`: se agrego `BUG-001 / Causa 4` para documentar el caso de Vercel Preview con variable `ADMIN_PASSWORD` ausente o diferente.
- `src/lib/aiProvider.ts`: se corrigio el ID del modelo LM Studio de `gemma-4-e4b-uncensored-hauhaucs-aggressive` a `google/gemma-4-e4b`, que es el identificador real mostrado por LM Studio.
- `.store/data.json`: se actualizo la configuracion actual de `mono-001` para usar `lmstudio / google/gemma-4-e4b`.

## Verificacion

- `npm run build` paso correctamente con Next.js 16.2.4.
- Se volvio a ejecutar `npm run build` despues del ajuste del modelo LM Studio y paso correctamente.

## Pendiente operativo

- En Vercel, configurar `ADMIN_PASSWORD` en el mismo environment del link usado:
  - Preview si se usa `webapp-git-...vercel.app`.
  - Production si se usa el dominio final.
- Despues de cambiar variables en Vercel, redeployar para que el cambio tome efecto.
- Si el servidor local ya estaba corriendo con la configuracion anterior en memoria, refrescar el admin y guardar de nuevo la configuracion de `mono-001`, o reiniciar `npm run dev`.
